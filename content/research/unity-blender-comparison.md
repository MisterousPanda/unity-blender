# Unity and Blender, for a beginner who will later use an LLM

Checked 2026-10-11. Official manuals are the authority for Unity and Blender behavior. Vendor pages are the authority for Grok, Marble, Dreamina, and Higgsfield. Where a claim comes from a guide, a model card, or a forum thread, it is marked. Product UIs and model ids move quickly.

## What each tool is best at

**Blender** is a 3D creation suite. Its job is to make the asset: mesh, sculpt, UVs, texture bake, materials, armature, and animation, then render a still or a frame sequence. Blender 5.2 ships three engines. EEVEE is a realtime rasterizer that can preview and also finish frames. Cycles is a path tracer for physically based stills and animation. Workbench is a fast modeling preview. Cameras, lights, and materials are shared, with features that exist in only one engine. ([Blender render introduction](https://docs.blender.org/manual/en/latest/render/introduction.html), [render engines](https://docs.blender.org/manual/en/5.2/render/render_engines.html))

**Unity** is a real-time engine. Its job is the thing a person plays or uses: scenes, input, physics, UI, audio, lighting that holds a frame rate, and a build for a device. Everything in a scene is a GameObject. Behavior is components on that object (Transform, Mesh Filter, Mesh Renderer, Camera, Rigidbody, Collider, scripts). Project files (models, textures, materials, prefabs, C#) are assets you instance into scenes. A scene can be a level, a menu, or a cutscene. ([Unity key concepts, Unity 6](https://docs.unity3d.com/6000.2/Documentation/Manual/key-concepts.html))

They complement each other. Blender authors the model and the motion clips. Unity assembles those assets into an interactive world.

## Differences a beginner will feel

**Scene model.** In Blender, objects share data-blocks (one mesh, many objects; one material, many users). Collections group objects for visibility and organization, and one object can sit in several collections. ([Collections](https://docs.blender.org/manual/en/latest/scene_layout/collections/collections.html)) In Unity, the hierarchy is parented GameObjects. A prefab is the reusable template. The same conceptual "chair" is a mesh data-block in Blender and a prefab plus components in Unity.

**Units.** Unity’s physics and lighting expect 1 meter in the world to be 1 unit in the imported model. ([Preparing model files](https://docs.unity3d.com/Manual/models-preparing.html)) Blender’s scene unit system (Metric / Imperial) and Unit Scale change what the UI displays. The manual says Unit Scale does not change internal behavior, including physics. ([Scene properties](https://docs.blender.org/manual/en/5.2/scene_layout/scene/properties.html)) Work in Metric with Unit Scale 1 and model at real size, so a person is about 1.8 Blender units tall. Unity’s importer defaults differ by format: FBX file scale 0.01, `.blend` file scale 1, with a Convert Units option. A wrong pairing is why a character arrives about 100× off. Check against a 1 meter cube. Do not trust an exporter preset you have not measured.

**Axes.** Blender is Z-up and right-handed; the manual describes it as Y forward, Z up (the front view looks along +Y). For a Y-up application the long-standing FBX mapping is −Z forward, Y up. ([FBX add-on, Blender 3.2 manual](https://docs.blender.org/manual/en/3.2/addons/import_export/scene_fbx.html) — older page; the axis description matches current practice.) Unity is Y-up and left-handed. Unity Support says to enable Bake Axis Conversion on import when the source axis differs, and that the mesh can also look the wrong size. ([Unity Support: imported FBX looks different](https://support.unity.com/hc/en-us/articles/10706367652756-Why-does-the-imported-FBX-model-look-different-from-other-applications))

**Materials.** Blender shades with nodes (Principled BSDF and friends). EEVEE and Cycles share that node graph. FBX has a fixed material model, so the exporter can carry slots, names, and a limited wrapper, not the node tree. ([Same FBX manual](https://docs.blender.org/manual/en/3.2/addons/import_export/scene_fbx.html)) Procedural colors have to be baked to images before export. ([Blender baking docs, cited in a practical export guide](https://www.wafrat.com/a-comprehensive-guide-to-exporting-models-from-blender-to-unity/)) Unity then needs its own material: a shader plus textures. Unity Support states that each application’s renderer differs and the imported model should use a Unity material. Blender’s roughness and Unity’s smoothness are inverses of the same idea (smoothness ≈ 1 − roughness). Built-in and URP often store smoothness in a texture alpha; HDRP packs metallic, AO, and smoothness into a mask map. That packing is practitioner consensus from Unity discussions, not a single manual page. ([Thread](https://discussions.unity.com/t/transferring-game-assets-from-blender-to-unity/1588309/1)) Normal maps from Blender are OpenGL-style; set the Unity texture type to Normal map.

**Animation.** Blender stores motion in Actions (F-curves of keyframes), layered in the NLA editor. The object uses an action the way a mesh uses a material. ([Actions](https://docs.blender.org/manual/en/latest/animation/actions.html), [NLA](https://docs.blender.org/manual/en/5.2/editors/nla/introduction.html)) Unity imports that as animation clips: a linear recording of the motion in the file. Gameplay playback is an Animator Controller (states, blend trees, parameters a script sets) or a direct Animator call. Simple clips can also be keyed inside Unity. ([Key concepts](https://docs.unity3d.com/6000.2/Documentation/Manual/key-concepts.html), [Animation from external sources](https://docs.unity3d.com/Manual/AnimationsImport.html)) Shape keys become blend shapes; Unity wants smoothing groups in the FBX if you need blend-shape normals. ([Preparing model files](https://docs.unity3d.com/Manual/models-preparing.html))

**Lighting.** A Blender light exists to feed EEVEE or Cycles. A Unity light is a component in a real-time budget. URP and HDRP differ in how many real-time lights they shade and in fidelity; baked lightmaps, light probes, and reflection probes carry lighting that cannot be computed fully every frame. ([Render pipeline feature comparison, Unity 6](https://docs.unity3d.com/6000.2/Documentation/Manual/render-pipelines-feature-comparison.html), [pipeline choice](https://docs.unity3d.com/2023.1/Documentation/Manual/BestPracticeLightingPipelines.html)) Export the mesh. Rebuild the lighting in the engine you ship.

**Export and import.** Unity’s production recommendation is FBX. Proprietary files, including `.blend`, are supported only as a convenience: Unity launches a local Blender and converts through FBX, and Unity says not to use those formats in production. Textures are not assigned automatically on that path. ([Proprietary model formats](https://docs.unity3d.com/Manual/HOWTO-ImportObjectsFrom3DApps.html), [Animation import](https://docs.unity3d.com/Manual/AnimationsImport.html)) Copy textures into the project (a `Textures` folder is the documented habit). Do not embed media in the FBX; Unity extracts it and the import gets slower. ([Preparing model files](https://docs.unity3d.com/Manual/models-preparing.html))

glTF 2.0 is Blender’s real-time interchange format (metal/rough PBR, meshes, skins, animation). The manual names Unity among engines that support it. ([glTF 2.0, Blender 5.2](https://docs.blender.org/manual/en/latest/addons/scene_gltf2.html)) Unity’s built-in model pipeline is still FBX. glTF import is the separate official package `com.unity.cloud.gltfast`. A March 2026 checklist reports that glTFast’s animation path is complete for the legacy Animation system and needs more setup for Mecanim, and that WebP textures in a GLB are a poor match for Unity’s texture importer. ([Cinevva checklist](https://app.cinevva.com/guides/blender-to-unity-export-checklist)) That package detail was not re-read from the glTFast changelog on 2026-10-11. Treat it as likely, then confirm in Package Manager.

**Real-time vs offline.** Unity has to produce a frame on a schedule while physics, input, and gameplay run. Blender Cycles can spend a long time on one accurate frame. EEVEE is realtime inside Blender and can be a final render; it is still a DCC renderer, with its own limitations, and it does not produce a player build. ([EEVEE](https://docs.blender.org/manual/en/latest/render/eevee/))

## A practical pipeline

1. **Block out scale in Blender.** Metric, Unit Scale 1, a 1 meter cube in the file as a ruler. Model the prop or character at real size. Apply object scale before export (the mesh scale should be 1,1,1). Put the origin where the object should pivot in-game (feet for a character, center of the seat for a chair).
2. **Author the asset in Blender.** Mesh, UVs, image textures (power-of-two PNG or TGA is the boring, reliable choice), armature, actions. Bake modifiers that are not an armature deform. Name material slots for what they are (`body`, `metal`), knowing the nodes themselves will be rebuilt.
3. **Export a snapshot, not the whole `.blend`.** Selected objects only. Leave Blender cameras and lights out unless you have a reason to import them. FBX for anything skinned or for clips that must land in an Animator Controller. glTF/GLB for a static prop when you are using glTFast and the materials are metal/rough. Re-import the FBX into a clean Blender scene once and confirm size and orientation before Unity sees it.
4. **Import in Unity and measure.** Enable Convert Units. If the model is on its side, enable Bake Axis Conversion. Compare to Unity’s 1 meter cube. Extract or replace materials with a URP/HDRP Lit material. Invert roughness into smoothness. Set normal-map texture type. Generate lightmap UVs if the mesh will be baked.
5. **Make it a game object.** Prefab. Collider that can be simpler than the render mesh. Animator Controller that maps clips to states. Lights, probes, and scripts live here. The `.blend` stays the art source. The FBX or glTF is a handoff. The prefab is what the game instances.

## Wrong jobs

People hit these often:

- **Hero modeling inside Unity.** ProBuilder and primitive cubes are for prototyping and blockout. Unity’s own key-concepts page says in-editor modeling is a poor fit for the final asset, and that polished models should be created in 3D software and imported. ([Key concepts](https://docs.unity3d.com/6000.2/Documentation/Manual/key-concepts.html))
- **A shippable game inside Blender.** Blender simulates rigid bodies and plays animation for rendering. It does not build the player, the UI, or the platform target. (UPBGE is a separate game fork; it is not the Blender you learn for asset work, and it is not Unity.)
- **Expecting the Blender look to survive the file.** Cycles volumetrics, shader nodes, and compositor passes are frames, not engine materials. EEVEE looking close to a game does not mean those settings exported.
- **Exporting the lighting rig as the game.** Rebuild lights in Unity for the chosen pipeline and for a frame budget.
- **One giant Blender scene as the level.** Export assets. Place them in a Unity scene, or use Unity Terrain for landscapes. A film-layout `.blend` full of cameras is the wrong file to drop in Assets.
- **Fixing scale by eye, or by a random scale factor typed twice.** Measure a 1 meter reference. The FBX 0.01 default plus an extra scale bake is the usual 100× error.
- **Using a rendered movie as character animation.** An mp4 has no skeleton. Clips come from actions on an armature (or from keyframes inside Unity).

## What you still have to understand if an LLM drives the tool

MCP lets the model call the editor. It does not give the model taste, and it does not make a wrong file format into a right one.

- **You own the check.** After every agent edit, look at: scale versus the 1 meter cube, which way is forward, feet on the ground, applied scale of 1, normals, material slots, and whether the action you wanted is the one that exported. The Blender Lab MCP page shows a scene analysis that missed a modifier’s real polygon count. The model’s summary can be incomplete even when the tool ran. ([Blender Lab MCP](https://www.blender.org/lab/mcp-server/))
- **You own the vocabulary.** You need to know GameObject versus mesh data-block, prefab versus collection, action versus Animator state, collider versus visible mesh, and roughness versus smoothness. Otherwise you cannot tell a successful tool call from a plausible mess.
- **You own destructive risk.** Blender’s lab MCP server runs model-written Python in Blender with no guard against deleting data or sending it out. Blender’s page recommends a machine without sensitive files. Blender itself has no built-in LLM connection; you add Blender 5.1+, an add-on, a client, and that server. ([Blender Lab MCP](https://www.blender.org/lab/mcp-server/))
- **Unity MCP is a beta bridge into the Editor, not a modeler.** As of Unity’s 11 May 2026 post, the official server ships with the AI Assistant package and needs Unity 6 (6000.0+), a project on Unity Cloud, and the AI tools beta. It can read the hierarchy, create and edit GameObjects, read and write components, edit C# scripts, read the console, and inspect build settings. The first external client connection must be approved in Project Settings. Unity says the beta can change or go away. ([Unity MCP announcement](https://unity.com/blog/unity-ai-mcp-how-to-get-started), [package manual](https://docs.unity3d.com/Packages/com.unity.ai.assistant@2.0/manual/unity-mcp-overview.html)) A widely used third-party server (MCP for Unity / Coplay) also exists and supports older editors. Do not assume a tutorial’s tool names match the official server.
- **Tell the model the constraints it cannot see.** Real-world meters, axis, “do not export cameras,” “FBX, selected armature only,” target pipeline (URP or HDRP), and poly budget. Ask it to report object scales and dimensions before it “fixes” them.
- **Generated pictures are references.** A beautiful render is not topology, UVs, or a rig. Accept the pixels, then decide what must become a mesh.

## Where Grok, world models, Dreamina, and Higgsfield plug in

**Grok is the default for creations and additions.** xAI’s Imagine API generates and edits images and video. It does not emit a mesh, an FBX, or a Unity prefab. Current documented surface (Imagine overview, fetched 2026-10-11):

- Images: `grok-imagine-image-2.0`. Text to image, and edits. Multi-image edit takes up to 5 sources (combine subjects, transfer style, compose a scene). Up to 10 images per generation request.
- Video: `grok-imagine-video-1.5` for text-to-video, image-to-video, and reference-to-video (up to 14 reference images and 3 voice references, with first, last, and mid frames pinnable). Clips up to 15 seconds. Video edit and video extend are documented on `grok-imagine-video`. Confirm the model id in the docs before a long job; the split between 1.5 and the older video model is easy to mix up. ([Imagine overview](https://docs.x.ai/developers/model-capabilities/imagine), [video generation](https://docs.x.ai/developers/model-capabilities/video/generation))

Use Grok for the picture and the motion study: concept frames, style additions on a still you already have, a turnaround sheet, a short camera move, an extended clip. Feed a Grok still onward when you need 3D. Keep the mp4 as reference or as a final video, not as an Animator clip.

Community MCP servers wrap this API (for example [grok-media-mcp](https://github.com/pongsakornp/grok-media-mcp)). They are not xAI’s official editor bridge. The API itself is the stable contract.

**World models** split into two kinds. Pick by whether you need a file you can open next week.

- **Persistent 3D.** World Labs Marble turns text, images, panoramas, or video into a world you can export. Gaussian splats (PLY/SPZ) are the high-fidelity look and need a splat plugin in Blender or Unity. A separate collider GLB is for physics and is the wrong mesh to render. High-quality textured GLB (about 600k triangles, plus a vertex-colored mesh around 1M) is an offline export on the Pro plan and can take up to an hour. World Labs warns of holes, floaters, and blobby surfaces on thin, transparent, or poorly covered areas. ([Marble mesh export](https://docs.worldlabs.ai/marble/export/mesh), [Unity splats](https://docs.worldlabs.ai/marble/export/gaussian-splat/unity), [Blender splats](https://docs.worldlabs.ai/marble/export/gaussian-splat/blender)) A Grok image is a natural Marble input. Clean the mesh in Blender, then FBX/glTF into Unity.
- **Tencent HY-World 2.0** is the same class of tool: text or images to meshes and 3D Gaussian splats aimed at Blender, Unity, Unreal, and Isaac Sim. Its model card contrasts this with video world models. WorldMirror 2.0 (reconstruction) is the open piece; other stages were still rolling out on the project site. Confirm what is actually downloadable before you plan a pipeline around it. ([HY-World 2.0 on Hugging Face](https://huggingface.co/tencent/HY-World-2.0), [project site](https://hyworld.dev/))
- **Video world models** (the HY-World card names Genie 3, Cosmos, and HY-World 1.5) produce pixels you watch. They are a reference for Grok or for layout, in the same bucket as a Grok clip. This brief did not re-check whether Genie 3 added a mesh export after those pages were written. If a product only plays a video, it does not belong in the FBX step.

**Dreamina** (ByteDance / CapCut) is a video finish, with Seedance 2.5 as the model their Blender workflow names. The documented handoff is a clay or blockout *render* uploaded as a reference video. Their own workflow page says this path does not import FBX, OBJ, GLB, or `.blend`. Rigging is optional because Seedance invents the motion from the reference and a prompt. ([Seedance 2.5 Blender workflow](https://dreamina.capcut.com/seedance/seedance-2-5-blender-model-workflow)) Use it when you want a Blender layout to become a generated shot. Grok remains the tool for the creations and the additions (edits, composites, extensions). Dreamina does not replace the mesh pipeline.

**Higgsfield** is the plug that can land geometry inside Blender, and it is also another video front-end. The official Blender add-on (Blender 5.1+, Windows or macOS; Linux was not listed on 2026-10-11) is a bar over the viewport: Scene Builder writes editable geometry into the open scene, 3D Model drops a mesh at the cursor (they name Meshy 5, with UVs and PBR maps), Character Animation writes a rig and keyframes as Blender bones and actions, and Image / Video / Camera / Asset cover the rest. Video there is Seedance 2.5. Generation is in their cloud and spends credits. A bridge at `bridge.higgsfield.ai/mcp` lets an agent drive that add-on. ([Higgsfield for Blender](https://higgsfield.ai/plugins/blender), [integrations help](https://higgsfield.ai/creator-hub/help-center/integrations/external-integrations-higgsfield)) Their Seedance help page says a clip cannot exceed 30 seconds. ([How to use Seedance](https://higgsfield.ai/creator-hub/help-center/ai-models/how-do-i-use-seedance))

Use Higgsfield when the result must be a mesh or a rig in the Blender file you already have open. Use Grok when the result is a picture, an edit, or a clip. Both video tools output pixels; neither writes an Animator Controller.

### One pass through the tools

Grok still or short clip (the design) → if you need a whole space, Marble or HY-World mesh/splat, then Blender cleanup → if you need one prop or character, Higgsfield 3D inside Blender or a hand-built mesh → Blender UVs, bake, rig, 1 meter check → FBX (skinned) or glTF (static) → Unity prefab, materials, collider, Animator, lights. Dreamina or Higgsfield Seedance, and Grok video, sit beside that chain as the shot you show people. Grok image edit and video extend are how you add to a creation without starting over. None of those generators replace the 1 meter check or the Unity material rebuild.
